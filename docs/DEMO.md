# 시연 스크립트 (①~⑦, 약 8분)

준비: `make setup` 1회 → `make demo` → 지갑 http://localhost:3000 (모바일 폭으로), 검증기관 http://localhost:3001 (데스크톱). 3000 이 사용 중이면 스크립트가 지갑을 3010 으로 띄우고 주소를 출력한다.
리허설 없이 전체 흐름을 확인하려면 `make e2e` (Playwright 가 ①~⑥ 과 ③′ 을 15초 안에 재현하고 `docs/screenshots/` 를 갱신한다). ⑦은 `E2E_ISSUER_DOWN_CMD="pkill -f dbp_issuer" make e2e` 로 함께 재현할 수 있다(끝나면 발급기관을 다시 띄워야 한다).
발표 노트북 한 대로 진행할 때는 브라우저 창 두 개를 좌우로 배치한다. QR 대신 6자리 코드 입력이 가능하다.

> 페르소나: 대구 북구 거주 68세 1인 가구 "김복례"(가명·합성 데이터), 월 소득 100만 원, 연소득 1,200만 원, 신용평점 하위 20%(창구 자체 조회). 발급받는 사실 11개(대구광역시 4 + 사회보장정보원 7).
> 시연 상품은 2026년 현행 기준이다: **햇살론 일반보증**(2026.1.2 개편 — 근로자햇살론·햇살론뱅크 통합, 은행·저축은행 모두 취급), **새희망홀씨**(연소득 4,000만 원 이하 또는 신용평점 하위 20%이면서 5,000만 원 이하, 은행권 전용). 혜택패스가 증명하는 것은 소득 요건뿐이고, 재직·사업 3개월 이상과 소득 증빙 요건·신용평점은 창구가 자체 확인한다(규칙 번들 `daegu-eligibility@2026.2` 에 넣지 않음).
> 한 줄: **공공이 판정한 자격을 시민이 보유하고, 은행 창구에 참·거짓만 제출한다.** (조회형 → 보유형)
> 보여줄 3성질: ① 값이 아니라 참·거짓 ② 1회 발급 → N개 창구 ③ 발급기관도 중계자도 제출 이력을 모른다. "종이 증명서를 없앤다"는 말은 쓰지 않는다.

## 예상 질의 → 화면으로 답하기
- **공공 마이데이터로 이미 되지 않나?** → ⑥ 비교 패널: 공공 마이데이터가 해결한 것은 서류 조달이다. 전달되는 것은 여전히 원문 항목 전체이고, 기관마다 다시 조회되며, 이용 내역이 3년 보관된다. 혜택패스는 공공 마이데이터를 대체하지 않고 2단계 입력으로 쓴다(원문은 발급기관에서 멈춘다).
- **서민금융 잇다가 하고 있지 않나?** → ⑦ + ③′: 잇다는 비대면 조회·추천 플랫폼이고 조회형이다. 상담이 창구로 넘어가면 자격 확인은 다시 원문 문제가 된다. 혜택패스는 시민이 보유한 참·거짓을 어느 창구에나 반복 제출하고, 검증은 발급기관을 거치지 않는다.
- **복지멤버십이 이미 하고 있지 않나?** → ② 화면: 공공 복지는 "복지멤버십 안내 대상"으로만 표시하고, 혜택패스는 그 다음 단계(창구 증명)와 복지멤버십에 없는 은행·민간 혜택을 맡는다.
- **민간인증서·전자증명서로 다 되지 않나?** → ③ 요청 확인 화면: 인증서는 "본인"을 확인하지만 "연소득 3,500만 원 이하"라는 사실은 증명하지 못한다. 혜택패스는 그 사실을 공공 발급기관 서명으로 전달한다.
- **상품 기준이 바뀌면?** → 2026.1.2 햇살론 개편을 실제로 반영한 경로로 답한다: 규칙 번들을 `2026.1` → `2026.2` 로 버전을 올려 원장에 새로 등록했다(원장의 (번들, 버전) 항목은 불변, D-03·D-21). 증명서에는 판정에 쓴 번들·버전·해시가 들어 있어 검증기관이 원장과 대조한다. 창구 프리셋은 상품을 취급하는 업권과 함께 관리한다(새희망홀씨 = 은행만).
- **김복례는 68세인데 햇살론 일반보증 재직 요건은?** → 재직·사업 3개월 이상과 소득 증빙은 신용평점처럼 창구가 자체 확인하는 요건이다. 혜택패스는 소득 요건(연소득 3,500만 원 이하) 한 가지를 원본 없이 증명하는 부분만 맡는다.
- **실제 기관이 발급하는가?** → 발급기관 `/.well-known/issuer` 와 `docs/DECISIONS.md` D-09: 모사 발급기관이며 모바일 신분증·마이데이터 어댑터로 교체되는 구조(`IssuerDataSource`).
- **키를 잃어버리면?** → 관리 화면 폐기 + 재발급. 자격의 원천은 지갑이 아니라 발급기관.
- **AI 가 틀리면?** → ②의 배지와 인용 검증. `services/ai` 테스트: 존재하지 않는 조항을 인용한 추천은 노출되지 않는다.
- **블록체인이 꼭 필요한가?** → ④ 네트워크 격리 + 원장 조회 체크리스트: 검증기관은 발급기관에 묻지 않고도 공개키·폐기 상태·규칙 버전을 확인한다. 발급기관은 제출 시점·상대를 모른다.

## 리허설 초기화
- 발급기관: `curl -X POST localhost:8001/admin/demo/reset` (복지기관은 8003). 지갑: 설정 → **지갑 초기화**.
- 규칙 번들 `2026.2` 로 바뀐 뒤 처음 리허설할 때는 지갑을 초기화해 이전 버전(`2026.1`)으로 발급된 증명서와 캐시를 지운다.
