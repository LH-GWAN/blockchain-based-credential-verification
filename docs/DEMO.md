# 시연 스크립트 (①~⑤, 약 6분)

준비: `make setup` 1회 → `make demo` → 지갑 http://localhost:3000 (모바일 폭으로), 검증기관 http://localhost:3001 (데스크톱). 3000 이 사용 중이면 스크립트가 지갑을 3010 으로 띄우고 주소를 출력한다.
리허설 없이 전체 흐름을 확인하려면 `make e2e` (Playwright 가 ①~⑤ 를 8초 안에 재현하고 `docs/screenshots/` 를 갱신한다).
발표 노트북 한 대로 진행할 때는 브라우저 창 두 개를 좌우로 배치한다. QR 대신 6자리 코드 입력이 가능하다.

> 페르소나: 대구 북구 거주 68세 1인 가구 "김복례"(가명·합성 데이터), 월 소득 100만 원, 신용평점 하위 20%.

| # | 화면 | 클릭 | 보여줄 것 · 멘트 요지 | 예상 |
|---|---|---|---|---|
| ① | 지갑 `/` → `/credentials` | 시민 선택(김복례) → **내 지갑 만들기** → **증명서 받기** → 동의 화면 **동의하고 발급받기** | 사전 판정은 단말 안에서 끝났고(개인정보 전송 없음), 동의 화면에 "증명서에 담기지 않는 정보: 이름·주민번호·주소·소득 금액"이 명시된다. 발급된 카드에는 **충족 여부만** 있고 소득 금액은 어디에도 없다. iM뱅크 카드(신용구간)는 은행이 따로 발급했다 → 기관 간 개인정보 공유 없음 | 60초 |
| ② | 지갑 `/benefits` | 카드 3개 확인 → 근거 조항 펼치기 → **AI가 받은 정보 보기** | 배지 "판정: 규칙 엔진 v2026.1 / 설명: AI". AI 는 적격 목록 안에서 설명만 했고, 인용 조항은 정책 DB 에 실재한다. "AI가 받은 정보" 시트에 범주값(65+, 1인 가구, ≤48%)만 있고 원본 수치가 없다. 채팅에 "생계급여는 왜 안 되나요?" 질문 | 60초 |

| ④ | 검증기관 `/result/[id]` | 자동 갱신 | ✅ 자격 충족 / 발급기관: 대구광역시 / 유효 / 체크리스트 5개 ✓ / **총 소요 ms** / 영수증 트랜잭션 해시. 터미널에서 `make demo-isolation` → 검증기관 컨테이너가 발급기관에 닿지 못함 (compose 사용 시) | 45초 |
| ⑤ | 발급기관 관리 `:8001/docs` 또는 지갑 `/history` → 검증기관 `/attack` | 대구시 관리: 해당 증명서 **폐기** → 지갑에서 새 요청에 다시 제출 → ❌ **폐기된 증명서**. 검증기관 `/attack`: 재사용·만료·위조·타인 증명서 버튼 4개 | 각 공격이 어떤 사유 코드로 차단되는지 (NONCE_REUSED, NONCE_EXPIRED, VC_SIG_INVALID, HOLDER_MISMATCH). 폐기는 원장 상태목록 버전이 올라가 즉시 반영된다 | 90초 |

## 예상 질의 → 화면으로 답하기
- **실제 기관이 발급하는가?** → 발급기관 `/.well-known/issuer` 와 `docs/DECISIONS.md` D-09: 모사 발급기관이며 모바일 신분증·마이데이터 어댑터로 교체되는 구조(`IssuerDataSource`).
- **키를 잃어버리면?** → 관리 화면 폐기 + 재발급. 자격의 원천은 지갑이 아니라 발급기관.
- **AI 가 틀리면?** → ②의 배지와 인용 검증. `services/ai` 테스트: 존재하지 않는 조항을 인용한 추천은 노출되지 않는다.
- **블록체인이 꼭 필요한가?** → ④ 네트워크 격리 + 원장 조회 체크리스트: 검증기관은 발급기관에 묻지 않고도 공개키·폐기 상태·규칙 버전을 확인한다. 발급기관은 제출 시점·상대를 모른다.

## 리허설 초기화
- 발급기관: `curl -X POST localhost:8001/admin/demo/reset` (iM뱅크는 8003). 지갑: 설정 → **지갑 초기화**.
