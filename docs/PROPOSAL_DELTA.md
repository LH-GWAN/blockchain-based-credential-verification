# 제안요약서(2026-09-14 개정판) 대비 실제 구현 차이 — 제출 전 문서 수정용

개정판 제안요약서(제목 "공공이 판정한 복지 자격을 은행 창구에서 소득 노출 없이 증명하는 AI·블록체인 인프라")를 기준으로 한다.

| 제안요약서 서술 | 실제 구현 | 수정 제안 |
|---|---|---|
| 구조도: 발급기관 "대구시 · 복지기관 (공공)" | 대구광역시(`did:dbp:daegu`, 주민등록·가구 사실) + 사회보장정보원 모사(`did:dbp:welfare`, 수급·소득구간·연소득 사실) 2개 인스턴스 | 2) 처리 흐름 ④에 "복지기관 = 사회보장정보원(사회보장정보시스템) 모사" 한 줄 추가 |
| 구조도: 검증기관 "은행 · 저축은행 창구" | iM뱅크 지점 + iM저축은행(모사) 프로필, 용도 프리셋 4종(서민금융 상담·햇살론뱅크·새희망홀씨·감면) | 5) 시연 시나리오에 "햇살론뱅크 프리셋: 연소득 3,500만 원 이하 1개 항목만 제출" 명시 |
| "햇살론뱅크 지원 대상 기준(연소득 3,500만 원 이하, 또는 신용평점 하위 20%이면서 연소득 4,500만 원 이하)" | 규칙 그대로 구현. 신용평점은 VC 로 발급하지 않고(`issuerOf: self`) 은행 자체 조회, 지갑 사전 판정에만 사용 | 3) 차별점에 "신용평점은 은행이 자체 조회하므로 시민이 증명할 대상이 아님" 각주 |
| 주요 기능 1 "민간 혜택까지 포함한 AI 탐색·설명" | 정책 13개 = 공공 복지·교통 7(복지멤버십 안내 대상) + 은행 서민금융 3(햇살론뱅크·새희망홀씨·소액생계비대출) + 민간 감면 3(통신·전기·도시가스). 지갑은 "은행·민간 창구 혜택(복지멤버십에 없음)" 을 먼저, 공공 복지는 "복지멤버십 안내 대상"으로 짧게 표시 | 데이터셋 칸 "샘플 정책 5~10개" → "13개(공공 7 + 은행·민간 6)" |
| "W3C VC 2.0 + Ed25519 전자서명" | W3C VC 2.0 데이터 모델 + JWS(EdDSA) 봉투형 증명(vc+jwt / vp+jwt) | 기술 스택 "증명 발급" 칸에 "(JWS 봉투형)" 추가 |
| "합성 시민 30명 × 정책 5개 = 150건" | 30명 × 13개 = **390건** 100% 일치 (TS/Python 동일 해시 `0x2032a0…dc15`) | 숫자 갱신 |
| "Hyperledger Besu 권한형 네트워크(QBFT) 또는 EVM 테스트넷" | 기본 시연 Hardhat, Besu QBFT 4노드 실기동 검증(배포·발급·검증·폐기·PII 스캔) | "개발·시연: Hardhat / 권한형: Besu QBFT(검증 완료)" |
| "한국어 지원 LLM API + RAG" | Anthropic Claude(`claude-opus-5`) + 정책 문서 컨텍스트 주입 + 인용 검증 + 템플릿 폴백. 시스템 프롬프트에 "복지멤버십 안내 대상은 짧게, 은행·민간 창구 혜택은 자세히, 창구 제출 안내 포함" 규칙 | "RAG" → "정책 문서 컨텍스트 주입(소규모 RAG)" |
| "개인정보 항목 70% 이상 감소 (약 10개 → 약 3개)" | 개인정보 항목 10개 → 2개(80%). 햇살론뱅크 용도는 1개(90%). 발급기관·유효상태는 증명서 메타데이터로 분리 | "10개 → 1~2개(80~90%)" 로 갱신 |
| "검증 2초 이내" | Hardhat 50회 p95 13ms, Besu 28ms | 측정값 기입 |
| "고령자 포함 사용자 5명 중 4명 이상 3분 내 완료" | **미측정** | "계획"으로 표기하거나 삭제 |
| 5) 시연 5단계 | Playwright E2E 가 5단계 + 햇살론뱅크 프리셋 제출 + 공격 4종 + 이력 대조를 자동 재현, 스크린샷 `docs/screenshots/` | 5) 자유 기재란에 스크린샷 삽입 |
| "OpenID4VCI / OpenID4VP (확장)" | 미구현, 매핑표만 `docs/ARCHITECTURE.md` | "확장 계획" 유지 |
