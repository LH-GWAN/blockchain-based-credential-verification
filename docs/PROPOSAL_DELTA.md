# 제안요약서 대비 실제 구현 차이 (제출 전 문서 수정용)

제안요약서 2) 구조 및 기술, 5) 자유 기재 항목에서 아래를 실제 구현에 맞게 조정한다.

| 제안요약서 서술 | 실제 구현 | 수정 제안 |
|---|---|---|
| "W3C VC 2.0 + Ed25519 전자서명" | W3C VC 2.0 데이터 모델 + **JWS(EdDSA) 봉투형 증명(vc+jwt / vp+jwt)** | 기술 스택 표 "증명 발급" 칸에 "(JWS 봉투형, VC-JOSE)" 추가 |
| "샘플 정책 5~10개" | **9개** (생계·주거·교육급여, 차상위, 기초연금, 에너지바우처, 통신요금 감면, 소액생계비대출, 대구 어르신 도시철도 무임) | "9개" 로 확정 |
| "합성 시민 30명 × 정책 5개 = 150건" | 30명 × 9개 = **270건** 100% 일치 | 숫자 갱신 |
| "Hyperledger Besu 권한형 네트워크(QBFT) 또는 EVM 테스트넷" | 기본 시연은 **Hardhat 로컬 노드**, Besu QBFT 4노드 compose 제공 (`chain/besu`) | "개발·시연: Hardhat / 권한형: Besu QBFT compose" 로 명시 |
| "Next.js 또는 React 기반 PWA" | Next.js 15 PWA (지갑) + Next.js (검증기관 화면) | "Next.js 15" 확정 |
| "한국어 지원 LLM API + RAG" | Anthropic Claude API(`claude-opus-5`) + 정책 문서 컨텍스트 주입(in-context retrieval, 정책 ≤10개라 벡터 DB 불필요) + 템플릿 폴백 | "RAG" → "정책 문서 컨텍스트 주입(소규모 RAG)" |
| "PostgreSQL (MVP: SQLite)" | SQLite (발급기관), 메모리(검증기관 요청·결과, AI 세션) | 그대로 |
| "개인정보 항목 70% 이상 감소 (약 10개 → 약 3개)" | 개인정보 항목 10개 → **2개** (80% 감소). 발급기관 식별자·유효상태는 개인정보가 아닌 증명서 메타데이터로 분리 표기 | "10개 → 2개(80%)" 로 갱신, 메타데이터 각주 |
| "AI에는 범주 값만 전달" | Pydantic `extra=forbid` allowlist 6개 필드로 강제, `/audit/last-payload` 로 시연 | 그대로, 시연 방법 추가 |
| "검증 2초 이내" | `scripts/bench_verify.py` 측정값을 TEST_REPORT 에 기록 | 측정값으로 갱신 |
| "고령자 포함 사용자 5명 중 4명 이상 3분 내 완료" | **미측정** (사용성 평가 미실시) | "계획" 으로 표기하거나 삭제 |
| "OpenID4VCI / OpenID4VP (확장)" | 미구현. 매핑표만 `docs/ARCHITECTURE.md` | "확장 계획" 유지 |
| "시연은 ①~⑤ 5단계를 연속으로" | Playwright E2E 가 5단계 + 공격 4종 + 이력 대조를 8.5초에 자동 재현 (`make e2e`), 스크린샷 14장 | 5) 자유 기재란에 스크린샷 삽입 (docs/screenshots/) |
| "검증 2초 이내" | Hardhat 50회 p95 13ms, Besu QBFT 검증 28ms (발급은 블록 대기 포함 0.7초) | 측정값 기입 |

추가로 넣을 만한 것: 발급기관별 '아는 필드' 분리(D-04), 상태목록 무작위 인덱스(D-05), 검증기관 네트워크 격리 시연, 소득인정액 단순화 고지(D-06).
